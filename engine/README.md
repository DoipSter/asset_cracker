# asset_cracker_engine

The Asset Cracker paper-trading engine as a pure Dart package: the pricing model, the six
strategies, Kalshi's fees, accounting and settlement. No Flutter imports, so it can run inside
the app, as a headless program, or in a test.

**Simulation only.** It is given prices and keeps imaginary balances. There is no code here
that talks to an exchange, and nothing that could place an order.

It is a port of `kalshi_trader.py` at the repo root, which stays the reference until this
package has replaced it. See `docs/flutter-port-scope.md`.

## Layout

| File | |
|---|---|
| `lib/src/model.dart` | Constants, strategy parameters, `probYes`, `kalshiFee`, `Market` |
| `lib/src/account.dart` | One strategy's account: entries, exits, the Lottery rule, settlement |
| `lib/src/trader.dart` | All six accounts for a coin, volatility, the learned index offset, reports |
| `lib/src/store.dart` | `Clock` and `Store` interfaces, in-memory versions, CSV quoting |
| `lib/src/file_store.dart` | `Store` on disk, same file names and formats as the Python app |
| `lib/src/pyfloat.dart` | Number handling that matches CPython (see below) |
| `bin/replay.dart` | The parity gate |

Two deliberate differences from the Python:

- **The clock is a parameter.** The Python reads `time.time()` inside the engine; here a
  `Clock` is passed in, which is what makes a replay deterministic.
- **Files are behind an interface.** `Store` can be memory, disk, or a phone's app folder.

## Matching Python's arithmetic

The gate compares trade logs character for character, so `pyfloat.dart` reproduces the
places where Dart and Python differ:

- `pyRound`: Python rounds exact ties to even (`round(0.125, 2)` is `0.12`); Dart rounds up.
- `pyRepr`: how the csv module writes floats (`7.8`, `1e-05`); Dart switches to exponents at
  different sizes.
- `pyFloorDiv`: Python's float `//` is derived from `fmod`, not from flooring `a / b`.
- `pySum`: plain left-to-right addition, as Python's `sum` did up to 3.11. From 3.12 `sum`
  compensates for rounding and can differ in the last bit. The fixtures were recorded on 3.9.
- `erf`: `dart:math` has none. This is fdlibm's algorithm, within one unit in the last place
  of the true value. CPython uses the platform C library's `erf`; on macOS that was itself up
  to 3 units out (measured, `tool/erf_truth.py`), so probabilities agree with the Python to
  about 2e-16 and not bit for bit.

`test/pyfloat_test.dart` checks all of these against about 15,000 values generated by CPython
(`tool/make_vectors.py`).

## Running

    dart pub get
    dart test
    dart run bin/replay.dart ../tools/parity/fixtures/2026-09-20_40min

Result on the 40-minute fixture (2026-09-20, Dart 3.13.4, macOS arm64): 12,562 calls replayed;
all 4,733 steps agree (volatility and index offset identical, probabilities and edges within
2.2e-16, same side and same bet/no-bet call for every strategy); 60 trade rows identical;
saved state identical.
